## 内容结构

### 01 硬件演进

| 对比维度 | 传统基础设施（CPU） | AI 基础设施（GPU） |
|----------|-------------------|-------------------|
| 计算模式 | 逻辑分支、整数运算 | 大规模稠密矩阵乘法（FP16/BF16） |
| 瓶颈资源 | 网络 I/O、CPU 核心数 | 内存带宽（单机）、网络带宽（集群） |
| 核心挑战 | "访存墙" | + "通信墙"（网络带宽比内存带宽低 3-4 个数量级） |
| 扩展思维 | 无状态 + 负载均衡 | 模型并行/数据并行/流水线并行 |

### 02 从"去IOE"到"AI大型机"

- AI 集群呈现"AI 大型机"特性：专用硬件 + 专用网络，集中式架构
- DeepSeek-R1 / QWen3-235B 千亿级参数需千卡集群
- 传统分布式理念（横向扩展）在 AI 时代部分失效
- 微秒级延迟等待也会造成巨大算力损耗

### 03 PCA 架构解耦

- **P** (Processing / 数据处理 / GPU 计算)
- **C** (Control / 控制编排 / 调度框架)
- **A** (Access / 访问接入 / 网关)

将大型机式的耦合架构拆解为独立模块，明确各层次边界

### 04 训练 Infra

- 数据集管理：入库、清洗、标注、检验
- 训练任务调度：资源分配、容错、监控
- 模型 checkpoint 管理：存储、版本、回溯

### 05 推理 Infra

| 层次 | 内容 |
|------|------|
| 硬件层 | GPU / HBM / NVLink / RDMA |
| 框架层 | vLLM / SGLang / TensorRT-LLM |
| 调度层 | 弹性扩缩 / 智能路由 / 混部 |
| 接入层 | 网关 / 鉴权 / 限流 / 负载均衡 |

## 核心观点

- **AI Infra 不是全新的领域**，传统后台工程积累的方法论（解耦、分层、容错、监控）大部分仍然适用
- **核心差异在硬件**：GPU 主导的计算模式带来"访存墙"和"通信墙"两大工程挑战
- **"AI 大型机"可能是阶段性的**，PCA 解耦是向更灵活架构演进的路径
- **训练和推理是两类不同 workload**，需要不同的 Infra 设计
